## Sarvam Full implementation

The new route `/development/voice-agents/sarvam` is a separate browser benchmark surface for Sarvam Voice Agents. It does not replace, modify or proxy the OpenAI Realtime implementation.

The browser surface uses Sarvam's official Web-channel embed generated by Sarvam Voice Agents. The portal reads the official public embed snippet from the server environment variable:

`SARVAM_VOICE_AGENT_EMBED_SNIPPET`

This variable must contain only the public Web embed snippet produced by Sarvam's dashboard. It must never contain a Sarvam API key, bearer token or another secret credential.

Until that environment variable is configured, the page intentionally renders an `Awaiting Sarvam embed` state and does not pretend the Sarvam agent is operational.

The embed loader accepts HTTPS scripts only from Sarvam-owned hosts and the Sarvam route receives a route-scoped CSP allowance plus `microphone=(self)`. The portal-wide microphone denial and default CSP remain unchanged everywhere else.

## Sarvam dashboard work still required

To make the benchmark operational, an authorized operator must complete these steps in Sarvam Voice Agents:

1. Create the INSUREIT renewal voice agent.
2. Configure its system instructions and the same synthetic renewal scenario used by the OpenAI benchmark.
3. Select/tune the Sarvam voice, language behavior, speed, pitch and pronunciation dictionary as needed for Indian English, Hindi and Hinglish.
4. Commit/test the Sarvam agent in the Sarvam console.
5. Enable the Web channel.
6. Copy Sarvam's official Embed snippet from the deployment/code section.
7. Add that public snippet directly to the Vercel server environment as `SARVAM_VOICE_AGENT_EMBED_SNIPPET`; never paste a secret into chat or source control.
8. Redeploy the portal and verify the browser microphone journey from an authenticated IT Super User account.

If Sarvam's current official embed loads an additional CDN/domain not already allowed by the route-scoped CSP, inspect the exact official snippet/network request first and add only the verified required origin. Do not broadly weaken the global CSP.

Do not connect this benchmark to real customers or PSTN telephony until the selected voice architecture and compliance boundaries are separately approved.

## Safety boundaries

- Browser benchmark only; no outbound customer calling is enabled.
- No production customer/policy tables are read or written by the Sarvam benchmark.
- No database migration is required for this feature.
- No quote, premium, IDV, NCB, insurer offer, discount, add-on or coverage term may be invented.
- Do not collect payment credentials, OTPs, Aadhaar/PAN, passwords or bank credentials.
- Do not store raw microphone audio in this phase.
- The OpenAI interaction-learning database remains specific to the existing OpenAI lab and is not silently reused as Sarvam training data.
