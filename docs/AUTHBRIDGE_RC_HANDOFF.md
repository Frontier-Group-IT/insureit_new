## Verified provider contract

AuthBridge supplied and the user successfully tested the Detailed RC service through the three-request UAT flow:

1. `POST https://www.truthscreen.com/InstantSearch/encrypted_string`
2. `POST https://www.truthscreen.com/api/v2.2/utilitysearch`
3. `POST https://www.truthscreen.com/InstantSearch/decrypt_encrypted_string`

Common headers:

- `Content-Type: application/json`
- `username: <UAT account username>`

Detailed RC request fields:

- `transID`: unique per lookup
- `docType`: `372`
- `docNumber`: normalized registration number

Provider notes:

- API is synchronous.
- IP whitelisting is not required.
- P95 is approximately 5–8 seconds depending on source.
- Use a 15–20 second provider timeout.
- AuthBridge stated no rate limit from its side.

## Repository implementation

### Gateway

File:

```text
infrastructure/icall-gateway/server.js
```

Implemented route:

```text
POST /uat/authbridge/rc-verification
```

Security and behavior:

- Protected by the existing relay Bearer secret.
- AuthBridge username remains server-side.
- Registration number is normalized and validated.
- A unique transaction ID is generated by the gateway.
- Encryption, RC lookup and decryption happen server-side.
- Provider credentials and opaque encrypted values are not returned to the browser.
- Provider failures are converted to controlled gateway errors.
- Sensitive provider response content is not logged.

Required Lightsail environment variables:

```text
AUTHBRIDGE_BASE_URL=https://www.truthscreen.com
AUTHBRIDGE_USERNAME=<stored privately>
```

The TruthScreen dashboard password is not used by the supplied Postman flow and must not be committed.

### Portal client

File:

```text
apps/web-portal/lib/authbridge-rc-api.ts
```

Exports:

- `lookupAuthbridgeRc(registrationNumber)`
- `normalizeVehicleRegistrationNumber(value)`
- `isValidVehicleRegistrationNumber(value)`

The client is server-only by design and uses the existing private gateway URL and relay-secret environment variables.
