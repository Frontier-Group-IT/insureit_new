# Accounts reconciliation workflow — Steps 1–2

Date: 2026-09-16

State: **IMPLEMENTED, NOT MERGED, NOT DEPLOYED**

## Purpose

Build the Accounts team's professional operating workflow gradually while preserving existing accounting controls and preventing unreviewed spreadsheet uploads from writing financial data.

## Step 1 — workflow foundation

The Accounts Dashboard presents a compact four-stage operating flow beneath the KPI cards:

1. **Expected pay-in** — uses the dashboard's filtered projected net pay-in and policy count.
2. **Insurer reconciliation** — links to the existing `/reconciliation` workspace.
3. **Brokerage billing** — links to the existing `/accounts/billing` workbench.
4. **Receipts & UTR** — links to the existing `/accounts/receivables` workspace.

The existing date / insurer / branch-placeholder filters and KPI calculations remain unchanged.

## Step 2 — controlled Excel template + preview

The Accounts Dashboard now includes a safe reconciliation Excel test flow:

- **Download Excel template** uses the active dashboard period and insurer filters.
- System/reference columns are generated by INSUREIT: Reconciliation ID, Policy Number, Insurance Company, Expected Pay-in.
- Accounts-editable columns are limited to Bill Number, Bill Amount, Bill Date, Paid Amount, Paid Date and UTR Details.
- Difference is deliberately not uploaded; the preview calculates **Expected Pay-in minus Bill Amount**.
- The workbook includes an Instructions sheet describing system-owned and Accounts-owned fields.
- **Upload Preview** accepts the generated `.xlsx`, validates headers, file size, row count, Accounts access scope, Reconciliation ID and live Expected Pay-in.
- Bill Amount requires Bill Number + Bill Date. Paid Amount requires Paid Date + UTR Details.
- Edited Expected Pay-in values are flagged and replaced by the live system value for preview purposes.
- Preview shows Ready / Warning / Error counts and a row-level validation table.
- There is deliberately **no Import button and no database write** in Step 2.

## Safety boundary

- No Supabase schema changes.
- No migration.
- No accounting formula changes.
- No reconciliation, billing, receipt or ledger write-flow changes.
- No sidebar changes; Accounts continues to expose only Accounts Dashboard and Other Recon.
- Uploaded workbooks are parsed for validation only and are not persisted by this implementation.

## Planned next step

After the template and preview UX are approved, add a controlled confirmed-import transaction model with audit history / idempotency, then implement the detailed Business MIS export that reproduces the Accounts team's required final spreadsheet format.
