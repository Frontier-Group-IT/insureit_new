# INSUREIT — Immediate n8n Intake extraction and bounded backlog recovery

## Why production lagged
Before this change, Vercel Cron ran every **five minutes**; `processAiQueueBatch` claimed **two** policy documents and processed them **sequentially**. A read-only production snapshot found 312 pending, 15 unsupported, 2 exceptions and 1 retryable failure. Across all open Intakes, 205 Motor files were named with prefix `3005`; the published n8n bridge is currently a trained **ICICI Lombard Product 3005** parser only.

The old Operations and Partner upload handlers independently launched the legacy Google Document AI OCR path after submission; the new n8n workbench queue was not connected to successful uploads. A correctly parsed n8n policy number remained in its separate private queue and did not populate the canonical `policy_intake_requests.ocr_fields`, so the existing shared duplicate policy-number detector had no reliable value to compare for failed-OCR Intakes.

## Solution
1. Original and replacement uploads, through **both** Operations `app/policy-intakes/actions.ts` and Partner/Branch `api/partner/policy-intakes/route.ts`, now schedule `processAiQueueBatch({preferredIntakeId})` in Next.js `after()` immediately after the successful CURRENT document save, whenever server-only n8n-primary queue mode is enabled. The old Google OCR fallback remains available **only if** this n8n rollout flag is switched off. This does not increase upload response latency for a remote parser call.
2. A new private, **service-role-only** `claim_policy_intake_ai_queue_v2` function claims one specifically uploaded Intake ahead of old backlog; it can also claim up to eight existing queue records per batch with `FOR UPDATE SKIP LOCKED`, retries ≤5, versioned current-PDF checks and four-minute leases. It upserts the specific Intake only on immediate calls; the scheduled backlog path reconciles all open Intakes.
3. The background worker drains **six** backlog Intakes per cron invocation, at most **three concurrent** signed-URL calls to n8n. The Vercel recovery schedule increases to **once per minute**. The safe theoretical ceiling becomes six per minute rather than two per five minutes; actual throughput depends on remote n8n PDF extraction duration and Cloud limits. Do not promise that every queued file will parse successfully.
4. `sync_verified_ai_intake_ocr_v1` provides an atomic service-only CAS for the **current** document, live lease, exact parser revision, strict 13 validation checks, nonempty policy number/name, empty original OCR and no saved draft. Only a still-processing **Motor** Intake may transition to Ready for Review and receive its verified n8n fields; no existing manually corrected data or customer match is overwritten. The canonical Register's `loadPolicyIntakeDuplicateMatches` now has its actual policy number and can classify a duplicate in both views.
5. Assessment runs the same registered-policy/earlier-Intake duplicate comparison on the n8n fields, plus a read-only check for other open Intakes with the same mobile but **different extracted insured names**. A shared number alone is not an identity conflict.

## Deployment / rollback sequence
- Run the full `Verify web portal` workflow for the **latest PR head SHA**, including regressions, TypeScript, lint, production build.
- Merge only when green; apply `20261117170000_ai_policy_priority_batch_queue_v2.sql` to the **linked INSUREIT production database**, verify the service-role RPC permissions and no records changed.
- Manually deploy the exact merged Git commit to the linked Vercel production project. Keep the existing `CRON_SECRET` and `INSUREIT_AI_QUEUE_ENABLED=true` production-only flags; do not create a second GitHub scheduler. Restore Vercel's manual-only Ignored Build Step setting immediately after the one-time authorized deployment.
- Verify queue counts over two scheduled ticks, new Intake handler path with a synthetic read-only manual test when possible, current document CAS guard and at least one **real** strict 3005 duplicate classification. Inspect errors before considering an increased concurrency cap.
- To pause all n8n jobs, set `INSUREIT_AI_QUEUE_ENABLED=false` and redeploy; to reduce throughput, set cron back to `*/5 * * * *` and worker MAX_BATCH to 2 / concurrency to 1 through a reviewed rollback. Existing v1 RPC still exists; the migration adds v2 and does not delete historical queue entries. Never blindly reset all unsupported attempts.

## Booking remains a separate transaction boundary
This release **does not automatically book customer/vehicle/policy master records**. It does not delete duplicates, bypass RTO/class/capacity/date validity/OTP, or authorize a bulk booking based on extraction alone. Currently the published ICICI 3005 parser does not provide full independent canonical issuance-date/customer-identity and coverage preflight for one-click bulk booking. Even a successfully extracted PDF must go through those checks. The previously introduced customer candidate popup is review-only; durable customer-link/create choices and one-click transactional conversion require a separate fully verified follow-up.

No new n8n workflow is created: the current active `INSUREIT - n8n Policy Intake OCR Bridge (DRAFT)` is called via its existing authenticated webhook, signed private PDF URL, and strict JSON validator. Google OCR remains unchanged outside the opt-in n8n primary queue path.
